### 修正1: API環境ラベルのバグ(`AppModel.swift`)

設定 → 端末情報とサポート の「現在の API 接続先」が **Production API と表示しながら URL は `kabuyomi-api-test`** を指していた(実機で確認、直下の広告診断も `API: test` と表示)。

原因: `APIBaseURLResolver.resolve` は **ビルド設定の `configuredBaseURL()` を UserDefaults のトグルより優先**する。ラベルはトグル由来の `usesTestAPI` を見ていたため実際の接続先と食い違う。→ **実際に解決された baseURL から導出**するよう変更。

DEBUG専用画面なのでエンドユーザーへの影響はないが、**開発中に「本番を叩いている」と誤認する**危険があった(課金・クレジット検証で事故りうる)。

### 修正2: 回答の結論部の文字サイズ(`RedesignRootView.swift`)

`structureAssistantMessage` は列挙型の回答("1つ目は…2つ目は…")で**複数文を意図的に結論へまとめる仕様**(既存テスト `testStructureAssistantMessageKeepsEnumeratedReasonsInConclusion` が約160文字の結論を期待している)。それを常に `.title3` で描くと**見出しサイズの塊が数行続く**。→ 65字 / 141字を境に `.title3` → `.body.semibold` → `.body` へ落とす。

## 6. 会話UIについて(未解決・要判断)

ユーザーから「会話するところのUIが微妙」との指摘。**実表示は確認できていない**(シミュレータは App Attest が使えずクレジット0で質問を送れないため)。コードから読み取った構造と評価:

- 利用者の発言 = 「質問」ラベル付きカード / 回答 = 「リサーチ回答」ヘッダ + AIバッジ + **結論 → 根拠となるポイント(箇条書き) → 留意点 → 根拠(出典チップ)**
- チャットバブルではなく**構造化ドキュメント形式**。リサーチ用途としては設計思想は妥当

**構造的な脆さ(本丸だと考えている)**:
`structureAssistantMessage` が LLM の散文を**文単位のヒューリスティクス**で結論/根拠/留意点に切り分け、さらに `assistantMetricRows` が**正規表現**で売上高・営業利益等を抽出している。**UIが約束する構造を、データが常に満たすとは限らない**。想定外の出力形だと「結論が1文で箇条書きが8個」「全部が結論に潰れる」といった崩れ方をする。

修正2で最悪の見え方(見出しサイズの壁)は緩和したが、**根治していない**。方向は2択:

- **(a) API側が構造化JSON(結論/根拠/留意点/指標)を返し、クライアントのパースを廃止** — 正しいが Worker + プロンプト + クライアントの三点セット変更で重い
- **(b) UIが構造を約束するのをやめ、散文 + 出典チップに簡素化** — 安いが情報設計が変わる

加えて **API は非ストリーミング**(仕様)なので、送信 → 保留 → 全文が一度に出る。現代のAIチャット体験と比べて待ちが死んで見える。これは別軸の課題。

**実際に会話画面を見るには**: Worker 側で allowlist されたデバイスキーが必要(設定 → 端末情報とサポート → 開発用オプション → Dev モード)。今回のシミュレータのキー(`…el2YEM`)は allowlist 外で有効化できなかった。実機か、allowlist 済みのキーで確認するのが早い。

- リサーチタブ: 検索欄 +「SEC資料から、会社を理解する」+ スターター銘柄5件
- 企業ワークスペース: **Apple Inc. 10-Q (2026/05/01)** の実データ — 概要、重要ポイント(売上高1,111.8億ドル・前年同期比+16.6%)、根拠リンク、主要数値(営業利益358.8億ドル +21.3% ほか)。AMZN も同様に正常

- 根拠詳細: **英語原文がそのまま表示** + 「日本語に翻訳(1クレジット)」

**ビルド時の注意(ハマりどころ)**:
`CODE_SIGNING_ALLOWED=NO` でビルドすると **Keychain entitlement が落ちて認証が通らず、会社の読み込みがローディングで止まる**。`CURRENT_SHIPPING_TRUTH.md` の「Simulator UI validation must use a normally signed local build」がそのまま再現する。**署名あり(Sign to Run Locally)でビルドすること**。

```
cd ios
xcodegen generate
xcodebuild -project Kabuyomi.xcodeproj -scheme Kabuyomi \
  -destination 'id=<iOS26のシミュレータUDID>' \
  -configuration Debug -derivedDataPath .build build
```

**シミュレータは iOS 26 系を使うこと**(実ユーザーの環境。iOS 18 で撮ると外観が実物と違う)。
