# Kabuyomi 会話主役 UI 仕様書 v1

> Historical / stale document. Not current v1 release truth. See `docs/release/RELEASE_TRUTH.md`.

## 目的
Kabuyomi の主役を `Summary を読む体験` から `決算書に質問する体験` へ移す。

この仕様書は、既存の
- [`kabuyomi_positioning_spec_v1.md`](./kabuyomi_positioning_spec_v1.md)
- [`kabuyomi_engagement_spec_v1.md`](./kabuyomi_engagement_spec_v1.md)

で定義した方向性を、**具体的な画面構成と初期挙動**に落とすための UI 仕様である。

---

## 一言定義
Kabuyomi は、

**「米国株の決算書に、日本語で質問するアプリ」**

として見える必要がある。

したがって、企業画面の主役は `Overview` ではなく `Chat` に置く。

---

## 現状の問題

### 1. Company 画面が読む前提
現状は企業画面で
- ヘッダー
- 指標
- `決算サマリー / AI チャット`

の順になっており、体験の主役が summary に見える。

### 2. Chat が補助機能に見える
今の Chat はタブの一つであり、

`気が向いたら試す機能`

に見えやすい。

### 3. 銘柄切り替えが会話中心ではない
今は
- Home
- Search
- Settings

の tab 構成で、企業をまたいだ会話の切り替え感が弱い。

---

## 設計方針

### 1. 企業画面は会話を主役にする
- 企業画面の初期タブは `Chat`
- `Overview` は補助情報として残す
- Chat の上に summary を小さく埋め込み、質問へ自然につなぐ

### 2. 銘柄選択はサイド導線に寄せる
- メイン体験は会話
- 銘柄選択は別導線
- 将来的には left drawer を導入する

### 3. 要約は捨てない
- Overview は残す
- ただし「主役」ではなく「会話を支える補助」にする

---

## 情報設計

## 1. 企業画面の上部タブ

### タブ構成
上部に 2 タブを置く。

- `質問する`
- `要点`

英語の `Chat / Overview` より、ユーザー価値が伝わる日本語を優先する。

### 初期表示ルール

#### 初回
その銘柄を**初めて開いたときは `質問する` を初期表示**にする。

理由:
- Kabuyomi の主役は chat であることを体験で伝えられる
- 差別化ポイントが最初に出る

#### 2回目以降
前回見ていたタブを復元する。

理由:
- 毎回 chat 固定だと、要点を見返したい時に不自然
- 継続利用ではユーザーの文脈を尊重する方がよい

---

## 2. `質問する` タブ

### 役割
Kabuyomi の主役画面。

### 画面構成

#### A. 小さい Overview カード
会話履歴の上に、簡潔な overview card を置く。

含める要素:
- 一言結論
- 今回の論点 1〜2 個
- 対応 filing 種別

目的:
- いきなり空会話に見せない
- 「何を聞けばいいか」を自然に作る

#### B. Suggested Questions
Overview card の直下に、

**今回の filing で聞くべき質問**

を 3〜5 個並べる。

例:
- `今回の決算で一番大きい変化は？`
- `利益率は改善した？`
- `リスク要因は何？`
- `地域別ではどこが伸びた？`

これらは filing 固有であることを優先する。

#### C. 会話履歴
中央の主領域。

表示ルール:
- assistant / user を明確に分ける
- 出典 chips は assistant 側に添える
- filing に根拠がないときは `確認できません` を明示する

#### D. Composer
最下部の入力欄。

方向性:
- ChatGPT に近い単一 composer
- placeholder は具体的にする

推奨文言:
- `決算のどこが気になりますか？`
- `例: 利益率は改善した？`

---

## 3. `要点` タブ

### 役割
読むための補助画面。

### 画面構成
- 一言結論
- 伸びたもの
- 悪化したもの
- 注目論点
- 主要指標
- 原文を開く

### 位置づけ
このタブは残すが、企業画面の主役にはしない。

要点タブは

`読む`

ための場所であり、

質問タブは

`考える / 深掘る`

ための場所である。

---

## 4. 銘柄切り替え導線

### 短期
現状の TabView は維持する。

理由:
- 既存コードを大きく崩さない
- beta 中の安定性を優先する

### 中期
企業画面を主役に据える再設計を行う。

構成案:
- メイン: 会話画面
- 左上: `銘柄` ボタン
- 押すと left drawer が開く

drawer 内要素:
- 検索バー
- ブックマーク銘柄
- 最近見た銘柄
- `NEW filing` バッジ付き銘柄
- スターター銘柄棚

### スワイプ挙動
left drawer を入れる場合でも、

**全画面 edge swipe 常時解放はしない。**

理由:
- iPhone の back gesture と衝突する
- 企業画面の戻る操作を壊しやすい

ルール:
- ルート画面では軽い右スワイプで drawer を許容
- 深い階層では left edge swipe は back を優先
- 常に開ける確実な手段として左上ボタンを置く

---

## 5. ブックマークの意味

### 現状
watchlist は「保存銘柄一覧」に近い。

### 新しい解釈
UI 上は次の意味に寄せる。

- `ブックマーク`
- `保存した銘柄`
- `よく聞く銘柄`

目的:
- 証券アプリの watchlist との競合感を薄める
- 「会話の入口」として自然にする

### 注意
内部データ構造は watchlist のままでよい。

変えるのは**意味付けとラベル**である。

---

## 6. Home の役割

### 方向性
Home は「ポートフォリオ」ではなく、

**どの企業の決算について次に質問するかを決める画面**

に寄せる。

### 必須要素
- 強い主コピー
- スターター銘柄棚
- 保存した銘柄
- `最近の filing` もしくは `新しい filing`

### 避けること
- 数字カードの羅列を主役にしない
- ウォッチ銘柄一覧だけで画面を終わらせない

---

## 7. 初回体験

### 理想導線
1. Home を開く
2. スターター銘柄棚から `AAPL` を選ぶ
3. 企業画面は `質問する` で開く
4. 上部の overview card を読む
5. suggested question を押す
6. source 付き回答を見る

この時点で、ユーザーが

`Kabuyomi は要約アプリではなく、決算書に質問するアプリだ`

と理解できることを目標とする。

---

## 8. 状態保持

### 保存するもの
- 銘柄ごとの最終表示タブ
- 会話履歴
- 最後に見た銘柄

### 保存しなくてよいもの
- drawer の開閉状態
- temporary composer draft（将来的には保持余地あり）

## 成功条件

次の条件を満たせば、この仕様は達成に近いとみなす。

1. 企業画面の主役が summary ではなく chat に見える
2. 初回ユーザーが 30 秒以内に 1 回質問できる
3. 同一 filing で 2 問以上続けて聞く行動が増える
4. ブックマーク銘柄の切り替えが会話中心に感じられる
5. Kabuyomi の印象が `読むアプリ` から `聞けるアプリ` に変わる

## 一言での完成像
Kabuyomi は、

**「決算サマリーを見るアプリ」ではなく、**
**「決算書に日本語で質問し、根拠付きで理解するアプリ」**

として感じられる状態を目指す。
