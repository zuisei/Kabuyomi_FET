# Kabuyomi v2 IA 刷新仕様(骨格の組み替え)

決定 2026-08-22。リリースオーナー指示「元の形を維持する必要はない。世の中が見やすいと
しているもので」。規範は**金融アプリの世界標準 = ウォッチリスト・ファースト**、
具体的には Apple 純正株価アプリの形(検索が上、自分の銘柄が板、その下にフィード)。
iOS ユーザーの筋肉記憶をそのまま使う。視覚言語は V2_REDESIGN_SPEC.md(terminal-grade
dark editorial)を継続。

## 新しいタブ構成

| 旧 | 新 |
|---|---|
| リサーチ(汎用発見リスト) | **ホーム** — 盤面+新着の1スクロール |
| 履歴 | **研究** — 過去の Q&A アーカイブ(会社別) |
| 設定 | 設定(不変) |

タブは目的地、各タブが NavigationStack を持つ、という7月ルールは維持。

## ホーム(Apple 株価型・1スクロール)

1. **検索バー**(最上部固定、現行の searchable を移設)
2. **盤面(ウォッチリスト)**: 保存済み+最近の会社を密な板行で。
   各行: ticker(tabular)/社名1行/最新 filing(form+日付)/**デルタピル**
   (売上 YoY を株価アプリのピル形式で。朱=増/青=減、キャッシュ済み metrics から)
   /未読ドット(filedAt > 最終閲覧、ローカル永続)
3. **新着**: トラック中の会社の filing をキャッシュの filedAt 降順で時系列に。
   行 = 会社+form+日付+要約の verdict 1行。タップで会社ワークスペースへ
4. **空状態**: 盤面が空のときだけ現行のスターター企業リスト+ミッション文を表示。
   発見リストとしての「リサーチ」画面は消滅し、この空状態と検索に吸収される

## 会社ワークスペース

Phase 1 の v2 ドキュメント(折りたたみヘッダー/数値グリッド/チップ/質問コンポーザ)を
そのまま使う。変更なし。ホームの板行・新着行のどちらからも同じ画面に入る。

## 研究タブ(旧・履歴)

会社ではなく **Q&A アーカイブ**が主役: 過去の質問と回答を会社別グループの時系列で。
Phase 2 の 1.5 行圧縮スタイルを流用。会社行タップで会社ワークスペースへ、
質問行タップで該当会話へ。

## データの現実(サーバー変更なし)

- 盤面・新着はすべて既存のローカルキャッシュ(saved/recent、filing cache、metrics)から導出
- 未読状態は「会社ごとの最終閲覧時刻」をローカル永続に追加(AppModel の管轄)
- 通知(push)は本仕様のスコープ外。新着はアプリを開いた時点のキャッシュで良い

## 動かさないもの(背骨)

- 課金・StoreKit フロー、クレジット画面(Phase 2 のまま)
- 出典チップの存在感、会社ドキュメントの編集的構成
- view はサービスを作らない。導出ロジックは pure support + AppModel の既存状態から
- 日本語文言(新規画面の新文言は可、既存文言の変更は不可)
- Dynamic Type / Reduce Motion / VoiceOver

## 検証基準

- iOS ユニット既存 222 件グリーン(タブ構造に依存するテストは新IAに合わせて更新可、
  ただし挙動アサーションを弱めない)+ 新規導出ロジック(板行・新着・未読)のテスト
- 空状態→初会社保存→盤面表示、の一連をシミュレータで実機確認

# Phase 4: タブを解いて、1本のストリームと常駐アスクバーにする

決定 2026-08-22。Phase 3 の3タブ(ホーム/研究/設定)を解体し、根の面を
**1本のストリーム + 底に貼りつくアスクバー**にした。視覚言語は
V2_REDESIGN_SPEC.md(terminal-grade dark editorial)のまま、
プリミティブ(`RedesignPrimitives.swift`)も Phase 3 の導出
(`HomeBoardSupport.swift`)も捨てずに引き継いでいる。

## なぜこの形か

1. **課金は質問1件ごと**。売っているのは画面ではなく質問なので、
   アプリの主役オブジェクトは質問でなければならない。
   質問の入り口が常に目の前にあることが、そのままプロダクトの形になる。
2. **filing は四半期に1度しか動かない**。ウォッチリストの盤面をホームに据えると、
   3か月のうち89日は昨日と同じ画面を見せることになる。板は「死んだホーム」だった。
3. **世の中の参照形は ask-first(Perplexity 型)**。しかもこのアプリは
   回答に出典チップを埋め込む作りを既に持っている。
   ask-first の弱点(答えの根拠が見えない)を、最初から埋めた状態で始められる。

## 新しい骨格

| Phase 3 | Phase 4 |
|---|---|
| ホーム(盤面 + 新着) | **盤面 → 会社ピッカーのシート** / **新着 → ストリームの資料イベント** |
| 研究(Q&A アーカイブ) | **ストリーム本体**(回答カード) |
| 設定タブ | **プロフィールのシート**(中身は既存の設定ルートのまま) |
| タブバー | **無くなった** |

- **ストリーム**: 「自分の質問と回答」と「追っている会社に資料が出た事実」を
  新しい順に1本へ流す。回答カード = 質問(小)+ 回答(読み面)+ 出典チップ + 会社/form/日付。
  資料イベント = 「{会社} の {form} が出ました」+ 提出日 + verdict の書き出し +
  提案質問チップ2〜3件。未読は Phase 3 の状態をそのまま使い、会社を開けば消える。
- **アスクバー**: 左 = 会社チップ(既定は最後に開いた会社 → 直近の保存済み → なし)、
  右上 = 残高「残り N」(常時表示、押すとクレジット画面)、下段 = 入力欄と送信。
  送信は会社ドキュメントのコンポーザと**同じ `AppModel.sendChat`** を呼ぶ。
- **会社ドキュメント**: Phase 1 のまま。ストリームのカード・会社チップ・検索から push。
  自前のコンポーザも持ち続ける = 入り口は2つ、送信の道は1つ。
- **上部バー**: 左にワードマーク(大タイトル)、右に検索アイコン(会社ピッカー)と
  プロフィールアイコン(設定シート)。

## 7月ルールの改訂(Phase 4)

7月版のナビ規約「タブは目的地、各タブが NavigationStack を持つ」は、
タブが無くなったので次のように置き換える。

1. **NavigationStack は根に1本**。会社ドキュメント / 資料一覧 / 引用詳細は push。
2. **設定・クレジット・会社ピッカーはシート**。設定シートは自前の NavigationStack を持ち、
   その中の push(クレジット / 端末情報)は Phase 2 のまま。
   シートは同時に1枚しか出せないので、3つの行き先を1つの状態にまとめている。
3. **左端の戻りジェスチャはどこでも効く**(根 → 資料詳細まで)。
4. **面を切り替えても AppModel も現在の会社もリセットしない**。
5. **ライフサイクルのコールバックからは質問を送らない**(7月ルールの維持)。
   Phase 4 ではこれをチップにも広げた。提案質問チップ・例示チップは
   `streamSuggestedQuestionIntent` を通り、この関数は `.prefill` しか返せない。
   送信が生まれるのは `streamSendIntent`(= 人が送信ボタンを押した)だけ。
   唯一の例外は同意ダイアログを閉じた直後の再開で、これは
   本人が押した送信の続きであり Phase 1 のコンポーザと同じ扱い。
6. **起動時に会社ドキュメントへ復元しない**(Phase 3 まではしていた)。
   根がストリームになった以上、開くたびに会社の中へ落とすと
   ストリームもアスクバーも見えないまま始まる。

## 送信の道が1本であること

無効理由(`"回答を作成中です"` / `"残高不足"` / `"端末認証を確認中"` /
`"質問機能を一時停止中"`)は `redesignComposerDisabledReason` が、
送信前の判定(空 / 塞がれている / 同意が要る / 送れる)は
`redesignAskPreparation` が1か所で決める。会社ドキュメントのコンポーザと
ストリームのアスクバーはどちらもこの2つを通り、最後に
`AppModel.sendChat(question:ticker:)` を呼ぶ。アプリ内の `sendChat` 呼び出しは
この2か所だけで、引数の形も同じ。

アスクバーだけは送信前に `loadCompany` を待つ。`sendChat` は資料の無い会社を
「企業データを先に読み込んでください。」で弾くため、
ワークスペースでは画面の `.task` が満たしている前提を、
ストリームでは押した側が満たしてから同じ道へ入る。

## データの現実(サーバー変更なし)

- ストリームは Phase 3 の `researchArchiveGroups` と `homeFeedRows` を土台に
  `streamItems` が1本へ混ぜる。上限は**回答にだけ**効かせる
  (混ぜた後に上限をかけると、質問を多く持つ人ほど資料イベントが窓の外へ出る)。
- 回答カードは会社ドキュメントを引き当て直さずに描けるよう、
  `ResearchArchiveEntry` が会社・回答本文・出典チップまで持つ形に広がった。
- 提案質問は会社ワークスペースの `buildSuggestedQuestions` と同じ文字列だけを使う
  (単体テストで部分集合を固定)。
- 導出は純関数(`StreamSupport.swift` / `HomeBoardSupport.swift`)、
  AppModel には薄い読み出し(`lastOpenedCompanyTicker` / `trackedConversationRecords`)だけを足した。

## 新規文言(Phase 4 の新規画面のみ)

既存文言は据え置き。空のストリームに置く例示3件だけが新規:

- 「この会社ってなにで稼いでんの？」
- 「前より儲かってる？」
- 「今回いちばん変わったのはどこ？」

このほか新規画面の見出しとして「ストリーム」「こんなふうに聞けます」「会社を選ぶ」
「会社を選ぶ(チップ既定)」「残り N」を追加した。

**持ち越し**: 設定の「スターター銘柄を表示」の副題「リサーチ画面に代表的な会社を表示します。」は
指す画面が無くなったが、既存文言のため変更していない。文言変更はリリースオーナーの判断。

## 検証基準

- iOS ユニット既存 245 件グリーン + Phase 4 の導出テスト
  (混在順序と同時刻の決定論・提案質問の選択と部分集合・宛先の既定値・
  プレフィルが送信にならないこと・無効理由の文言と優先順位)
- IA の構造テスト(KabuyomiUITests/ShellParityUITests)は新しい骨格に更新。
  「タブバーが無い」の代わりに「アスクバーは根にだけ貼りつき、
  ドキュメントの上には出ない」を固定する
- Dynamic Type AX3 でアスクバーとカードが縦積みになり、文字が切れないこと
- Reduce Motion で遷移が即時であること

**カードは行数を切らない**。資料イベントの verdict も、回答カードの質問と回答本文も
折り返す。ストリームのカードは「行」ではなく読み面で、途中で切ると実際に文末が消える
(アクセシビリティ監査が `Text clipped` で拾う)。回答カードに出すのは
`structureAssistantMessage` の結論だけで、根拠と留意点は会社ドキュメントの会話面に残る。

**実機確認で届かなかった面**: 回答カードだけは、確認に使った環境の残高が 0 で
(月額分 0/0・ウェルカム 0)、開発用 quota が Worker 側の allowlisted device key を
要求するため、1件も回答を作れず描画を確認できていない。
データ側は単体テスト(会社・回答本文・出典チップを持つこと)で固定してあり、
描画は Phase 1 で確認済みの `RedesignSourceChip` を流用している。
