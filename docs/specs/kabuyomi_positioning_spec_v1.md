# Kabuyomi ポジショニング改善仕様書 v1

## 目的
Kabuyomi の現状の弱さは、機能不足ではなく「最初の約束が弱い」ことにある。

今のトップ画面は、
- SEC を日本語で読む
- 10-K / 10-Q を読む
- AI チャットできる

という**手段の説明**に寄っており、ユーザーが「なぜ今このアプリを開くのか」が弱い。

この仕様書の目的は、Kabuyomi を

**「SEC を読むアプリ」ではなく、「米国株の決算変化を3分で掴むアプリ」**

として見せ直すことである。

---

## 変更しないもの
- iOS / Workers / sec-fetcher の技術構成
- 出典拘束
- 10-K / 10-Q 中心のスコープ
- source-bound chat
- beta 時点の広告 / 課金 freeze 方針
- 法的に投資助言アプリへ寄せない前提

この仕様は、**機能追加仕様ではなく、価値の見せ方と情報設計の仕様**である。

---

## 現状の問題

### 1. 手段を言っていて、結果を言っていない
現状のホームコピーは「SEC 提出書類だけを日本語で読む」になっている。

これは正しいが、ユーザーにとって重要なのは
- 何が変わったのか
- どこが伸びたのか
- どこが危ないのか
- 今回の決算で見るべき論点は何か

である。

### 2. 誰のアプリかが曖昧
「米国株に興味がある人」以上に絞れていない。

少なくとも v1 では、Kabuyomi は次の人に刺さるように見せるべきである。
- 米国個別株を触っているが、英語 filing を毎回読むのは重い人
- 決算で何が変わったかだけを早く掴みたい人
- ニュースや SNS ではなく、一次資料で確認したい人

### 3. 最初の一手が弱い
初回起動時に「何をすれば価値が出るか」が即座に見えない。

必要なのは抽象説明ではなく、
- まず AAPL を読む
- まず MSFT を読む
- 今回どこが強かったか聞く

といった**即体験導線**である。

---

## プロダクトの再定義

### 一言定義
Kabuyomi は、

**「米国株の決算変化を、一次資料ベースで3分で掴むアプリ」**

である。

### ユーザーに約束すること
Kabuyomi はユーザーに対して、次の 3 点を約束する。

1. 決算の要点を日本語で短時間に掴める  
2. 変化の根拠を source 付きで確認できる  
3. 気になった論点を、そのまま出典付きで深掘りできる  

### 約束しないこと
- 売買推奨
- 目標株価
- 株価予測
- ニュース集約
- ポートフォリオ管理

### Pro / 上位プランで検討する余地
現行 v1 では、Kabuyomi はニュースアプリではなく一次資料ベースの決算読解アプリとして見せる。

一方で Pro または将来の上位プランでは、**AI 付き web 検索**と**ニュースタブ**を追加候補として持つ。目的は「SEC の外へ逃げる」ことではなく、提出資料だけでは分かりにくい次の文脈を補うことである。

- 決算後の市場反応
- 直近ニュースと filing 上の論点の接続
- 経営陣コメント、業界イベント、規制・訴訟などの追加文脈
- ユーザーが次に聞くべき問いの提示

表現の軸は、**「一次資料で掴み、必要な時だけ外部文脈で確かめる」** とする。

候補コピー:

> Pro では、決算資料に加えて直近ニュースや web 情報も AI が整理。一次資料の根拠を軸に、株価反応や市場文脈までつなげて確認できます。

## 新しいメッセージ設計

### プライマリコピー

### セカンダリコピー
**10-Q / 10-K の要点、変化、リスクを日本語で。根拠はすべて一次資料。**

### 補助メッセージ
- 何が伸びたか
- 何が悪化したか
- 経営陣は何をリスクとして見ているか

### 避ける言い方

- filing を読む
- XBRL を読む
- AI で質問できる

これらは機能説明としては正しいが、ファーストビューの主役にしない。

## 画面ごとの仕様

## 1. Home

### 役割
Home は「機能一覧」ではなく、**価値の入口**にする。

### 必須要素
1. 強い主コピー
2. 一言で分かる補助説明
3. 即体験 CTA
4. 直近ウォッチ銘柄
5. 何を聞けるかの例

### 表示内容

#### ヒーロー領域
- 見出し: `米国株の決算変化を、3分で掴む`
- 補足: `10-Q / 10-K の要点、変化、リスクを日本語で確認。出典付きでそのまま深掘りできます。`
- サブ情報:
  - `一次資料ベース`
  - `出典付き`
  - `10-K / 10-Q 対応`

#### 即体験 CTA
優先順位:
1. `まず AAPL を読む`
2. `MSFT を見る`
3. `検索から始める`

beta では 1 個でもよい。重要なのは、**ユーザーが何を押すべきかを考えなくて済むこと**。

#### ウォッチリスト
今のカード構造は維持してよいが、冒頭に次の見出しを付ける。
- `追っている銘柄`

#### 下部説明
短く、1 ブロックだけ置く。
- `Kabuyomi は株価予測ではなく、企業の提出資料から「何が変わったか」を掴むためのアプリです。`

---

## 2. Search

### 役割
Search は「銘柄を探す画面」ではなく、**今すぐ読める決算を探す画面**にする。

### 必須要素
- 何を追加できるかが分かる
- その銘柄の対応 filing が分かる
- 押した後に何が起きるかが分かる

### 表示内容
- 見出し: `読む銘柄を追加`
- 補足:
  - `Kabuyomi は 10-K / 10-Q に対応しています`
  - `20-F / 6-K は v1 対象外`

### 検索カード
各カードで最低限見せるべき情報:
- ticker
- company name
- exchange
- `最新 10-K` または `最新 10-Q`

### 追加ボタンの意味
`追加` は内部的には watchlist 登録だが、UX 上は

**「この銘柄の最新決算を読む」**

に近い。

ボタンラベルは将来的に
- `追加`
- `読む`

のどちらが良いか A/B 余地あり。

beta 中は `追加` のままでもよい。

---

## 3. Company

### 役割
Company は「企業情報画面」ではなく、**1 本の決算の変化と論点を掴む画面**にする。

### 情報の優先順位
1. 一言結論
2. 何が変わったか
3. どこがリスクか
4. もっと聞く
5. 元資料に戻る

### ヘッダー
ヘッダーで最初に見せるべきもの:
- 会社名
- ticker / form type
- 一言結論
- 提出日
- 対象期末
- 原文を開く

### Summary タブ
`ハイライト` と `前期比の変化` は良いが、将来的には次の 3 つに整理する。
- `何が伸びたか`
- `何が悪化したか`
- `今回の論点`

v1 では、見出しや補助文だけでもこの方向へ寄せる。

### Chat タブ
Chat の価値は自由入力ではなく、**聞くべき問いが最初から出ていること**。

初期候補は以下を基本セットにする。
- `今期の決算で一番大きい変化は？`
- `利益率は改善した？悪化した？`
- `リスク要因は何？`
- `地域別ではどこが伸びた？`
- `経営陣は需要環境をどう説明している？`

## 初回体験仕様

### 目標
初回起動 30 秒以内に、ユーザーが

`Kabuyomi は、決算の変化を日本語で早く掴めるアプリだ`

と理解すること。

### 理想の最短導線
1. Home で主コピーを見る
2. `まず AAPL を読む` を押す
3. 一言結論を見る
4. `利益率は改善した？` を押す
5. source 付き回答を見る

この導線が成立すると、ツール説明ではなく体験で価値が伝わる。

## トーン仕様

### 目指す印象
- 静かな自信
- 一次資料ベース
- 余計な煽りがない
- 投機臭がない
- でも難しすぎない

### 避ける印象

---

## 受け入れ条件

次の条件を満たせば、この仕様は実装済みとみなす。

1. Home の主コピーが「何ができるか」ではなく「何が得られるか」になっている
2. Search で最新 filing 種別が見える
3. Company で一言結論が最上段の役割を持っている
4. Chat で「何を聞けばいいか」が最初から分かる
5. アプリ全体の説明が「SEC を読む」から「決算変化を掴む」へ寄っている
