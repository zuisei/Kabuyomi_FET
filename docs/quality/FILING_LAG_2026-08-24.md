# 決算プレス(8-K item 2.02)と 10-Q/10-K の時間差(2026-08-24 実測)

通知(提出書類の到着で知らせる)が**株価が動く瞬間に間に合うか**を確かめるための実測。
SEC の submissions API を直接叩いた数字で、推定ではない。直近4期。

`filingDate` ではなく **`acceptanceDateTime` を見ること**。EDGAR は受理が夕方の締切を
過ぎると `filingDate` が翌営業日に転がるので、日付だけ見ると実際より遅く見える。

## 結果: 遅れは二極化する

| 会社 | 8-K(2.02) → 10-Q/10-K | 実際の間隔(受理時刻ベース) |
|---|---|---|
| **MSFT** | 0 日 | **3〜4 分後** |
| **NVDA** | 0 日 | **11〜30 分後** |
| **AMZN** | 1 日(日付は転がる) | **約 2 時間後** |
| **TSLA** | 1 日(同上) | **約 5 時間後** |
| **AAPL** | 1 日 | **約 14 時間後**(翌朝) |
| **JPM** | **17〜31 日** | **数週間後** |

- **テック系は実質同時**。MSFT はプレス受理 20:07 → 10-Q 受理 20:10。
  この層では「提出書類の到着」を引き金にした通知が**スパイクに間に合う**
- **金融系は絶望的に遅い**。JPM は 8-K で決算を出してから 10-Q まで 17〜31 日。
  ここで 10-Q 通知を出しても、株価が動いた3週間後に届く

## 通知を作る場合の含意

1. 引き金は `acceptanceDateTime`。`filingDate` は翌営業日に転がるので使えない
2. **会社ごとに過去の間隔を計算し、間に合う会社にだけ通知を約束する**ことはできる
   (この実測と同じ計算をバッチで回せばよい)
3. 間に合わない会社(JPM 型)でスパイクに乗るには **8-K item 2.02 が要る**。
   これは現在**意図的にスコープ外**(LP・利用条件・`validate.mjs` の禁止表現・審査メモの
   すべてが「8-K は対象外」で揃っている)。広げるならその全部を動かす判断になる
4. 外国企業では同じ役割を **6-K の業績プレスリリース**が担う。
   判別は実装済み(`workers/src/lib/filings/six-k.ts`、`kind: results_release`)。
   **つまり「業績プレスを引き金にする」機構は、外国企業側には既にある**

## 再現

`docs/quality/` 配下のこの表は `data.sec.gov/submissions/CIK##########.json` の
`form` / `filingDate` / `items` / `acceptanceDateTime` から作った。
8-K は `items` に `2.02` を含むものだけを決算プレスとみなしている。
