# Docs

Kabuyomi documentation is organized by release use, operational ownership, and historical status.

Start with [INDEX.md](./INDEX.md). It is the maintained map for active v1 docs, v1.1 planning notes, historical docs, and test artifacts.

## Primary v1 Docs

- [release/RELEASE_TRUTH.md](./release/RELEASE_TRUTH.md): v1 submission source of truth
- [release/APP_STORE_SUBMISSION_NOTES.md](./release/APP_STORE_SUBMISSION_NOTES.md): App Store Connect review/privacy notes
- [release/TESTFLIGHT_READINESS_CHECKLIST.md](./release/TESTFLIGHT_READINESS_CHECKLIST.md): TestFlight/manual release checklist
- [legal/LEGAL_SITE_DEPLOYMENT.md](./legal/LEGAL_SITE_DEPLOYMENT.md): static legal site deployment notes
- [legal/APPLE_STORE_SERVER_CONFIG.md](./legal/APPLE_STORE_SERVER_CONFIG.md): Apple Store Server API setup for paid-credit verification
- [quality/V1_WORKER_CRITICAL_REVIEW.md](./quality/V1_WORKER_CRITICAL_REVIEW.md): latest v1 Worker answer-safety review packet

## Planning And Historical Docs

- [quality/](./quality/): Worker quality, architecture, and refactor planning docs
- [admob/](./admob/): rewarded AdMob runbooks and deferred v1.1/post-approval checklist
- [archive/old-specs/](./archive/old-specs/): old product specs; not current v1 release truth
- [archive/historical-handoffs/](./archive/historical-handoffs/): older handoffs, maps, scratch notes, and split plans

Historical docs may contain subscription-era, free/pro ladder, older quota, web-search, or pre-v1 release assumptions. If they conflict with the current code or [release/RELEASE_TRUTH.md](./release/RELEASE_TRUTH.md), use the release truth and current code.
