# Kabuyomi マーケティング計画(2026-08-24)

前提となる実測は `docs/quality/USAGE_REALITY_2026-08-24.md` と
`docs/growth/ASO_PROPOSAL_2026-08.md`。この文書は**次に何をやるか**だけを書く。

## 結論: 動かす数字は「インプレッション」1つだけ

App Store Connect の 90 日実測はこう繋がる。

```
インプレッション 294  ×  タップ率 10.2%  =  ページ表示 30  ×  13.3%  =  ダウンロード 4
```

最後の 4 は、本番 D1 の `installation_identities`(verified/full)の 4 件と一致する。

**確実に言えるのは「発見されていない」ことだけ**。294 インプレッションという数字は
それ自体が十分に小さく、疑う余地がない。
**一方で転換率(10.2% / 13.3%)は、まだ測れていない**。母数がページ表示 30・DL 4 なので、
13.3% の 95% 信頼区間はおよそ 4〜31% に広がる。「正常」とも「ひどい」とも読める幅で、
**この数字を根拠に何かを決めてはいけない**。

したがって当面の判断基準はひとつ。**その施策はインプレッションを作るか。**
作らないなら後回し。そして**インプレッションが増えて初めて転換率が測れるようになる** —
このキャンペーンは獲得施策であると同時に、**転換率の測定装置**でもある。

## いま入れた変更(2026-08-24、このリポジトリ内)

| # | 変更 | 効く経路 |
|---|---|---|
| 1 | `legal-site/public/robots.txt` / `sitemap.xml` を新規作成 | 検索エンジンが LP を辿れるようにする(いま robots.txt は 404 で index.html が返るだけだった) |
| 2 | ルート `index.html` から `/lp/` へリンク | LP がサイト内のどこからもリンクされない孤児だった。被リンクゼロのページは索引されない |
| 3 | LP の CTA に campaign token(`ct=lp` / `ct=lp-footer`)、末尾に2枚目の CTA | LP 経由の入手を App Analytics の Campaigns で分離。付けないと検索流入と混ざって効果が測れない |
| 4 | 回答カードに `ShareLink`(`AppPromotion.shareText`) | 口コミの経路がそもそも存在しなかった。共有 URL は `ct=app-share` |
| 5 | 回答成功3件以降に `requestReview`(`ReviewPromptGate`) | 評価2件では検索順位にも転換にも効かない。失敗直後や起動直後には出さない |
| 6 | `legal-site/scripts/validate.mjs` に LP と robots/sitemap の検査を追加 | LP は検査対象外で、禁止表現のガードが効いていなかった |

補足:

- **LP の「8-K」表記を落とした**。`validate.mjs` の `forbiddenClaims` は部分一致なので、
  「8-K には対応していません」という否定文でも引っかかる。
  意味は変えずに「それ以外の提出書類」と書き換えた。
- **共有本文には出所と免責を必ず入れている**。アプリ内では画面の注意書きが担っている役割が、
  共有先には付いていかないため(`AppPromotion.shareText` のテストで固定)。
